# 얼마였지 — MP1 할 일 앱 화면 만들기

## 구현 기능과 확인 순서

1. 처음 실행하면 `장보기 목록이 비었어요` 안내를 표시합니다.
2. 홈의 상품명 입력칸에 이름을 쓰고 `+` 또는 키보드 완료를 누르면 목록에 추가됩니다.
3. 항목이나 체크 상자를 누르면 완료 상태와 상단 완료 개수가 바뀝니다.
4. `screenshots/`의 빈 상태·추가 입력·목록·완료 화면을 확인할 수 있습니다.

현재 앱에는 다음 단계의 저장 기능도 포함되어 있어 재시작해도 기록이 유지됩니다.

## 프로젝트와 기준 소스

`얼마였지(how-much)`는 장보기 목록과 구매 가격을 기록하는 기존 Flutter 앱입니다.
이 제출물은 현재 앱의 같은 소스 스냅샷을 단계별 평가 기준에 맞춰 설명합니다.
과거 단계별 개발 시점의 버전이나 개발 프롬프트를 복원한 자료는 아닙니다.

- 기준: develop / PR #22(긴 영수증 이어붙이기) 병합 커밋 `d9e9ce4ab4f0343616a5151e739cff20c244ecdb`
- 제출 준비 중 메모 임시 사진 삭제와 후보 수정창 종료 처리를 보완했습니다.
- 런타임에는 장보기·구매 기록·영수증 OCR·자체 서버 동기화 기능이 함께 포함돼 있습니다.
- 실제 개인정보 대신 우유·계란·두부 등 가상 목록만 사용했습니다.

## 실행 절차

Flutter 3.47.5 / Dart 3.13.4, Android SDK 또는 Xcode가 필요합니다.
Flutter 3.38.5는 새 dartcv4 의존성과 SDK 고정 패키지가 충돌하므로 사용하지 않습니다.

```sh
cd app
flutter doctor
flutter pub get --enforce-lockfile
flutter run --dart-define=API_BASE_URL=
```

`API_BASE_URL=`은 서버 연결을 끄고 로컬 기능을 실행합니다. 앱이 자동으로 `.env`를 읽지는 않습니다.
Android 7.0(API 24) / iOS 15.5 이상을 대상으로 합니다. iOS는 최초 실행 전에 `cd ios && pod install`로 네이티브 의존성을 준비합니다.
처음 의존성과 Android 빌드 도구를 내려받을 때 인터넷이 필요합니다. CMake와 Ninja 실행 파일이 PATH에 있어야 합니다. macOS의 네이티브 시험 빌드는 Ninja 생성기를 사용합니다.
`dartcv4`의 영상 정합 네이티브 빌드가 포함되므로 첫 빌드는 시간이 걸릴 수 있습니다.

## 데이터 구조

`AppRow`의 `id`, `title`, `quantity`, `note`, `completed`, `revision`, `deleted`와 동기화 상태를 사용합니다.
장보기는 `purchase`가 없는 행이며 완료 여부는 `completed`입니다.
사진 경로는 장보기 기록이나 서버 데이터에 저장하지 않습니다.

## 검증 조건과 제약

- Android API 36.1 arm64 에뮬레이터에서 실제 앱 위젯을 실행하고 화면을 캡처했습니다.
- 문자 입력만 시험 키보드를 사용했습니다. SharedPreferences 저장과 OCR은 실제 네이티브 구현을 사용했습니다.
- 일반 앱 기록과 다른 시험용 저장 접두어를 사용하고 서버 연결을 껐습니다.
- 실제 휴대폰 검사, 기존 손글씨 오인식 해결, 수업 담당자의 통과 판정으로 설명하지 않습니다.
- 설치·빌드 캐시, 로컬 설정, 인증 정보, 원본 개인 사진과 내부 조사 보고서는 ZIP에서 제외했습니다.
- 원본 iOS 손글씨 회귀 사진은 제외했으므로 해당 RunnerTests의 사진 기반 시험은 원본 저장소에서 별도로 실행해야 합니다.
