# Android에서 세 OCR 엔진 독립 비교 — 2026-10-12

`test/receipt-ocr-models` 브랜치에서 실제 앱의 전체·부분 OCR 호출을 빌드별로 ML Kit, PaddleOCR, Tesseract 중 하나에 연결했다. 한 엔진의 결과로 다른 엔진을 보완하지 않는다. 기본 빌드는 기존 ML Kit를 유지한다.

모든 엔진을 같은 Ubuntu Android 15 / API 35 / x86_64 에뮬레이터에서 실행한다. 원본·보정 사진, 수량·금액·상품명·행 크롭과 백지 **217개**는 이전 시험과 같은 파일이며 실행마다 SHA-256을 확인한다. 트레이더스 작은 입력에는 같은 흰 여백을 붙인 **45개**를 별도로 사용한다. 외부 이미지 전처리·대비 보정은 추가하지 않는다.

## 실행 구성

| 엔진 | Android 구성 |
|---|---|
| ML Kit | Flutter 플러그인 0.16.0, 한국어 SDK 16.0.1 |
| PaddleOCR | 공식 Android SDK 고정 커밋, 기존 PP-OCRv5_mobile_det + korean_PP-OCRv5_mobile_rec 가중치의 ONNX 변환, ONNX Runtime Android 1.21.1, CPU 4스레드, 검출 최대 변 1600px |
| Tesseract | Tesseract4Android 4.9.0 / 코어 5.5.1, 이전과 같은 kor+eng 언어 파일, OEM LSTM, PSM 3·7·10 별도 실행 |

Paddle SDK의 원래 4000px 검출은 12MP 원본에서 Java 메모리 부족으로 종료됐고, 메모리 한도 확대 후에는 프로세스 메모리 약 1.9GB에서 종료됐다. 최종 시험은 메모리 한도 확대 없이 검출기 내부의 최대 변만 1600px로 제한한다. 입력 파일과 반환 좌표는 원본 기준이다. QuickBird OpenCV 4.5.3의 x86_64 로딩 오류 때문에 비교 모듈에서만 공식 OpenCV 4.12.0을 사용한다. 이 실패도 `failures/`에 보존했다.

이전 Ubuntu Paddle 실행은 PaddlePaddle 런타임과 4000px 검출, Tesseract는 코어 4.1.1이었다. 같은 가중치·사진이라도 실행 코드·내부 크기·코어 버전이 달라 결과가 달라질 수 있으므로 이전 결과를 덮어쓰지 않는다. 실기기·iOS 실행 성적으로 해석하지 않는다.

## 채점과 자료

`summarize.py`는 숫자 값, 상품명 전체 일치·문자 편집 오류율, 전체·행 사진의 **해당 위치와 값**을 각각 집계한다. 박스 중심이 사람 지정 정답 영역에 들어오는 숫자 하나만 성공으로 센다. 다른 행의 숫자나 엔진 간 결과를 가져오지 않는다. 이름은 한글 완성형/분해형을 NFC로 정규화하고 공백·기호·대소문자만 제외한다.

- `results/`: 엔진·입력·PSM별 실제 Android 원문·좌표·점수·실패·시간.
- `logs/`: 빌드 및 실제 실행 기록. 테스트 완료는 인식 정답을 뜻하지 않는다.
- `environment.json`: 기기·런타임·모델·언어 파일 해시와 실패 구성.
- `summary.json`, `field-results.csv`: 단독 영역 정답률.
- `localization-summary.json`, `localization.csv`: 전체·행 입력에서 값과 위치 정답률.
- `timings.json`: 첫 호출과 개별 호출 측정값. 디버그 에뮬레이터의 혼합 입력 시간이며 휴대폰 성능 순위로 해석하지 않는다.

실제 앱의 상품 자동 연결·사진 촬영 UI, 매장·날짜·손글씨 정확도는 이 엔진 비교 시험의 평가 대상이 아니다. Flutter 모의 응답 테스트는 실제 사진 인식 결과와 구분한다.

## 재현

모델 준비는 [비교 모듈](../../../app/android/ocr_compare/README.md)을 따른다. `run_android.py --engine mlkit|paddle|tesseract`는 설치 전에 비교 전용 패키지를 확인하고 `--no-uninstall`을 사용한다. `--suite padding`, `--psm 7`, `--psm 10`은 별도 실행이다. 모든 실행이 끝난 뒤 `python3 docs/ocr-comparison/20261012-android/summarize.py`로 해시·입력 누락을 확인하며 집계한다.

초기 실패 시험에서는 비교 설정이 적용되지 않은 기본 패키지가 테스트 종료 시 제거됐다. 이후 패키지 검사와 자동 삭제 방지 옵션을 추가했다. 기본 앱 재설치는 설치 상태 복구이며 기존 로컬 기록 복원과는 구분한다. 실기기는 변경하지 않았다.

## 완료된 비교 결과

Android 8회·총1,059건의 실제 실행 원문을 집계했다. 기본 입력은 각217건, 공통 여백은 각45건, Tesseract PSM7은210건, PSM10은 수량63건이다.

| 원본3장·21개 상품 | ML Kit | PaddleOCR | Tesseract PSM3 |
|---|---:|---:|---:|
| 수량 단독 영역 | 1/21 | 21/21 | 0/21 |
| 금액 단독 영역 | 20/21 | 21/21 | 5/21 |
| 상품명 전체 일치 | 5/21 | 8/21 | 1/21 |
| 전체 사진 수량 위치·값 | 15/21 | 15/21 | 4/21 |
| 전체 사진 금액 위치·값 | 19/21 | 21/21 | 3/21 |
| 행 사진 수량 위치·값 | 16/21 | 3/21 | 2/21 |
| 행 사진 금액 위치·값 | 19/21 | 20/21 | 4/21 |

Tesseract 단독 수량은 PSM3 0/21, PSM7 0/21, 숫자 제한 PSM10 3/21이었다. 상품명 완전 일치는 PSM3 1/21, PSM7 2/21이다. 설정별 성적을 합치지 않는다.

기본 입력의 ML Kit 실행 오류45건은 작은 크롭의 최소 크기 오류다. 공통 여백에서는 세 엔진 모두 오류0건이며 수량 ML Kit2/15·Paddle5/15·Tesseract0/15, 금액12/15·12/15·2/15였다.

삼선 펩시 수량 단독 입력은 Android Paddle에서1을 읽었으나 같은 숫자 행에서는 수량1을 놓쳤다. 위치 검출과 지정 영역 인식의 차이는 Android에서도 남았다.
