# Android 기본 Paddle 전환과 호환성 검증

사용자 요청으로 Android 전체·부분 영수증 OCR 기본 엔진을 Paddle로 바꿨다. 사진 보정·후보 선택·자동 연결·검토·저장·인증·동기화 흐름은 유지한다. iOS는 기존 ML Kit를 사용한다. `--dart-define=OCR_ENGINE=mlkit`로 기존 인식 경로를 명시할 수 있으며 자동 대체·결과 혼합은 하지 않는다.

## 최소 버전

기존 Android7.0(API24), iOS15.5를 유지한다. 요구사항 분석서 v1.0의 D-01은 지원 버전을 팀 결정 대상으로 두며 특정 최소 버전을 고정하지 않는다. 공식 Paddle Android 예제 모듈의 선언은 API26이지만, 실제 ORT1.21.1 AAR는 API24, OpenCV4.12.0 AAR는 API21이다. 소스의 API26 전용 호출을 검색하고 Android 라이브러리 린트와 API24 실제 실행을 확인한 뒤 모듈 최소 버전을24로 조정했다. `tools:overrideLibrary`로 최소 버전 검사를 무시하지 않았다.

## 실제 사진 서비스 시험

별도의 임시 Android7.0/API24/x86_64 에뮬레이터(emulator-5556)와 기존 Android15/API35/x86_64 에뮬레이터(emulator-5554)에서 각각 같은 교보 원본·수량 크롭 해시를 확인했다. 비교 채널은 사진 준비에만 사용하고 인식은 기본 `howmuch/receipt_ocr` 채널 및 실제 `OcrService()`에서 실행했다.

두 기기 모두 전체 초안에서 상품8개·숫자24개를 반환했고 포스트잇 이름과9,600원 후보를 확인했다. 서비스의 단독 영역 재인식은101 스티커 수량1을 읽었고, 사진·인식기 재사용의 기본/수량 세션에서도 각각1을 반환했다. 원문 실행 로그를 보관한다. 이 시험은 실제 사진 인식이며 전체 상품 자동 연결의 정답률 시험과 구분한다.

기본 APK와 시험 APK의 Paddle/OpenCV/ORT/C++ 네이티브 파일12개의 해시가 같음을 확인했다. 기본 APK는 기존 `com.todayone.todo`, minSdk24이며 Paddle 모델을 포함하고 시험 사진·Tesseract 라이브러리·언어 파일은 제외한다.

## 검증·환경·제약

- Flutter280개 통과·기존1개 건너뜀. 기존 ML Kit 응답 회귀 시험은 엔진을 명시했고 앨범 UI 모의 응답은 기본 Paddle 채널로 검증한다.
- 실제 서비스 시험은 API24·35 모두 통과. 기본 앱 debug APK 빌드·Paddle Android lintDebug 성공.
- 포맷 완료. 정적 검사는 기존 `screens.dart:806` 경고1개만 유지한다.
- 앱 `pub get`·Flutter 패키지 업그레이드·lock 변경은 없다. API24 시험용 SDK 시스템 이미지와 임시 AVD만 추가했다. 기존 AVD와 실기기 데이터는 변경하지 않았다.
- Android7 ARM 실기기·iOS 빌드와 전체 자동 선택 화면의 새 인식률은 아직 시험하지 않았다. 초기 검출 최대 변1600px·CPU4스레드 설정을 유지한다.
- 사용자의 후속 시험 요청으로 기본 Paddle debug APK를 emulator-5554에 `install -r`로 업데이트 설치하고 정상 실행을 확인했다. 데이터 초기화·실기기 설치·커밋·푸시는 하지 않았다. Windows의 전환 전 백업 ZIP을 유지한다.

기본 APK SHA256: `1024f32752dc1e43612097e233655802b20af02a38af76344c80d4f4959b7206`.

## 첫 상품 독립 확정 후속 수정

첫 상품의 이름·수량·금액으로 자동 판정 전에 검토 항목을 만든다. 나머지 후보의 추가/삭제/행 이동, 경계·중복·메타데이터 판정이 첫 상품의 값이나 체크 상태에 영향을 주지 않는다. 첫 입력 자체의 숫자 범위와 필수 값만 확인한다. 이름 병합은 확정 ID·이름·박스를 바꾸지 않는다.

실제 기본 Paddle 서비스를 사용한 교보 사진 자동 선택에서 포스트잇/670-5AN-5/알뜰팩, 수량1, 결제금액9,600, 체크true를 확인했다. 전체 OCR8개 상품 중 자동 검토5개로 생성돼 다른3개 후보의 누락은 미해결로 구분한다. 테스트284개 통과·기존1개 건너뜀. `first-review-real.log`는 실제 사진, `first-independent-tests.log`는 모의 후보 제어 흐름 회귀를 포함한다.
