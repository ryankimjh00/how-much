- Ubuntu 에뮬레이터 `emulator-5554`, 설치된 debug APK의 실제 Android ML Kit 호출 결과다. 모의 OCR 응답은 사용하지 않았다.
- APK SHA-256: `d1ee8643b82145d7ca6494b73e79f38b65b2ed0fa7614a9ac55b5188187d5570`.
- 원본은 사용자가 제공한 `20261007_222835.jpg`와 앱 캐시 `kyobo-receipt.jpg`. 보정 비교는 이전 실제 사진 테스트에서 저장한 `kyobo-perspective.png`를 사용했다. 이번에 새로 모서리를 선택하거나 원근보정하지 않았다.
- 각 사진을 현재 `OcrService.recognizePath`로 읽은 다음 첫 포스트잇, 첫 수량 1, 오른쪽 금액 9,600을 기준으로 `readAutomaticReceiptLines`를 호출했다. 수량 기준 영역은 읽힌 1의 중심에 폭 80px·높이 100px로 지정했다.
- 화면 탭을 통한 전체 흐름 테스트가 아니라 앱에 연결해 실제 서비스와 자동 선택 함수를 호출한 테스트다. 수량·금액은 UI와 같은 사진/인식기 재사용 및 병렬 세션을 사용했다. 사용자 기록은 저장하지 않았다.

- 원본 둘째 `101` 상품: 수량 1을 전체 OCR에서 서로 겹치는 두 후보로 읽었다. 기존 후보끼리는 중복을 합치지 않아 수량 연결이 모호해졌다. 수량 열에서는 1을 다시 읽었지만 연결이 확정되지 않아 부분 OCR 5회 후 수량 없음/체크 해제.

후보 누적 자체는 확인했지만 이미 읽힌 후보의 연결과 잘린 숫자의 성공 판정은 실패했다. 이 테스트에서는 앱 코드를 수정하지 않았다. 원문 후보와 모든 부분 OCR 응답은 함께 저장한 JSON/TSV에 있다.

## 수정 후 실제 사진 재검증

위 실패 기록을 보존하고, 수정 코드를 에뮬레이터에 연결해 hot restart한 뒤 같은 두 사진을 현재 ML Kit로 다시 읽었다. 설치 APK 자체를 다시 빌드한 것은 아니므로 위 APK 해시는 수정 전 패키지다.

각 시간은 1회 관측이다. UI의 프레임 대기가 빠진 서비스 호출이며 일반적인 속도 개선율을 보장하지 않는다. 상품명 오탈자는 일부 남아 있다. 실제 새 호출 결과는 `fixed-original.tsv`, `fixed-corrected.tsv`다. `receipt_kyobo_accumulation_test.dart`는 수정 전 JSON/열 응답 재생 테스트이며 이 실제 사진 재인식과 구분한다.

수정은 전체 OCR 안의 겹치는 동일 값 중복 제거, 이름 열에서 다시 확인한 행의 원본 이름 유지, 숫자 열 경계를 통과한 행의 상품별 세로 소속 확인, 읽힌 열 숫자 직접 재사용이다. 다른 상품 행과 서로 다른 값은 합치거나 임의 확정하지 않는다. 원문 행과 원본 초안은 유지한다.
