# 로컬 저장·자동 동기화·복구 코드

## 1. 작업 출처

## 2. 배경
수동 이메일 로그인·동기화를 보완해 가입 화면 없이 기기 간 기록을 이어 쓴다.

## 3. 목표
기기 저장을 우선하고, 서버 연결 실패나 계정 변경 때 기록을 보존한다.

## 4. 범위
복구 코드 신규 계정·기존 계정 복원, 계정별 로컬 저장, 자동 전송·재시도·충돌 선택. 기존 이메일 로그인도 유지한다.

## 7. 다음에 바로 해야 할 것
운영 Firebase 설정 후 두 기기에서 오프라인 수정→온라인 복원→충돌 선택을 확인한다.

## 8. 후속에 구현해야 할 것
기존 이메일 계정에 별도 복구 수단을 연결하거나 코드 교체·폐기가 필요하면 서버 인증 확장을 설계한다.

## 9. 결정된 사항
- `SharedPreferences`의 기존 v4 기록 형식과 Firestore `accounts/{uid}/state/main`을 유지한다.
- 복구 코드는 160비트 난수(32문자, 4자씩 8묶음)다. 원문은 발급 화면에서 한 번만 표시하고 저장·로그에 남기지 않는다.
- 식별자와 비밀번호에 서로 다른 SHA-256 해시를 사용한다. 기존 Firebase 비밀번호 인증과 UID 권한 규칙으로 같은 사용자임을 확인한다.
- 신규 코드 계정은 기기 기록을 복사한다. 원본 기기 기록은 보존한다. 복원 계정은 기기 기록을 자동 합치지 않는다.
- 기기 기록을 직접 가져올 때는 계정에 삭제 기록과 충돌을 포함한 기존 기록이 없어야 한다.
- 전송 중 수정은 잠시 차단한다. 미해결 충돌은 양쪽 값을 유지한다.
- 실패 시 pending과 기기 기록을 유지한다. 앱 활성 상태의 다음 주기에 재시도한다.
- 변경 없는 서버 문서는 다시 쓰지 않는다. 가격 공유도 같은 실행 중에는 성공한 변경을 반복 전송하지 않는다.

## 10. 아직 결정되지 않은 사항
운영 Firebase 프로젝트·실기기 검증 일정, 복구 코드 교체 정책.

## 11. 임시 구현 / 주의사항
- 코드는 접근 비밀이다. 분실하면 다른 기기에서 복원할 수 없고, 유출되면 해당 기록에 접근할 수 있다.
- `recovery.howmuch.invalid`는 메일을 받는 주소가 아닌 내부 계정 식별 영역이다. 인증 v1 규칙 변경은 기존 코드 호환성을 깨므로 ADR과 고정값 테스트를 함께 확인한다.
- 데이터가 200,000자 JSON을 넘으면 서버 전송을 거부하고 기기 기록을 유지한다.
- 새 백엔드 HTTP API는 추가하지 않는다. Firebase 인증·Firestore 계약과 예제는 `firebase/README.md`에서 관리한다.
