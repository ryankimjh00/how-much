## 2. 배경
가입 화면 없이 기기 간 기록을 이어 쓴다. 서버는 사용자 선택에 따라 Firebase에서 클러스터 API로 교체했다.

## 3. 목표

## 6. 현재 구현 상태
| 항목 | 상태 | 비고 |

| 앱 저장·동기화 | 완료 | 저장 후 700ms, 활성 상태 30초마다 재시도 |
| 자동 테스트 | 완료 | 계정 분리·충돌·오프라인·늦은 응답 보호 |
| 복구 코드 다시 보기 | 완료 | 발급·복원 후 보안 저장, 기존 세션은 코드 재입력 필요. 실기기 확인은 별도 |

| 두 물리 기기 | 재검토 필요 | 동시 요청 검증 완료, 두 아이폰 실사용은 별도 |

## 9. 결정된 사항
- SharedPreferences v4와 계정별 저장 키를 유지한다.
- 복구 코드는 160비트 난수다. 서버에는 해시만, 기기에는 코드와 세션을 Keychain/Keystore에 함께 보관한다. 일반 설정과 로그에 남기지 않는다.
- 계정 화면에서 보관한 코드를 오프라인·세션 만료 상태에서도 확인·복사한다. 로그아웃하면 기기의 코드와 세션을 함께 제거한다.
- 이전 버전의 세션에는 코드가 없다. 같은 계정의 코드를 재입력해 인증·보안 저장에 성공하면 다시 보기를 사용할 수 있다. 다른 계정의 코드와 저장 실패는 기존 계정·코드를 바꾸지 않는다.
- 신규 계정에는 guest 기록을 복사하고 원본을 유지한다. 복원 계정에는 자동 합치지 않는다.
- guest 가져오기는 계정에 삭제 기록·충돌을 포함해 기존 데이터가 없어야 한다.
- 전송 중 수정을 잠시 막고, 충돌은 양쪽 값을 유지한다. 실패한 pending은 다음 주기에 재시도한다.
- 세션 만료 때 로컬 계정 데이터를 지우지 않고 복구 코드 재입력을 받는다.
- 같은 실행 중 성공한 가격 공유는 동일 변경을 반복 전송하지 않는다.

## 10. 아직 결정되지 않은 사항
복구 코드 교체·폐기 정책.

## 11. 임시 구현 / 주의사항
이전 버전에서 코드를 분실했다면 서버의 해시로 원문을 복구할 수 없다. 기기 코드 보관은 별도 백업을 대신하지 않는다. 과거 Firebase 이메일·코드 계정은 자동 이관하지 않는다. 서버 계약·입력 한도는 [서버 문서](../../server/README.md)에 있다.
