## 1. 작업 출처
사용자 요청(2026-10-05), Parent #3, #8·#9·#10.

## 2. 배경
Firebase 대신 사용자의 Kubernetes 클러스터에서 데이터를 보관한다.

## 3. 목표

## 4. 범위

아이폰 계정 메뉴에서 복구 코드를 발급·보관하고 기록 연결을 시작한다. USB 연결 시 `app/integration_test/cluster_sync_test.dart`로 실제 Keychain 동작을 자동 확인한다.

## 8. 후속에 구현해야 할 것
자동 백업과 복구 코드 교체·폐기 정책.

## 9. 결정된 사항
- PostgreSQL 한 인스턴스, `longhorn-kr-single` PVC 2Gi.
- `https://howmuch.monithub.org`와 전용 Gateway·인증서. 기존 공용 Gateway는 유지한다.
- 해시만 서버에 보관하고, 기기 세션은 Keychain/Keystore에 저장한다.
- 세션 만료·서버 실패·충돌 때도 로컬 기록을 보존한다.
- Harbor는 비공개 `howmuch` 프로젝트와 전용 pull robot을 사용한다.
- 계약과 예제: [서버·Swagger 문서](../../server/README.md). 운영 절차: [배포 문서](../../deploy/README.md).

## 10. 아직 결정되지 않은 사항
자동 백업 저장 위치·주기와 복구 코드 교체 정책.

## 11. 임시 구현 / 주의사항
DB 한 인스턴스·볼륨 한 복제는 고가용성이 아니다. 계정당 최대 1,000행·200KB, 세션 365일·최근 20개 제한. API 한 프로세스 요청 제한과 365일짜리 Harbor pull robot은 확장·만료 전에 재검토한다. 과거 Firebase 이메일·복구 코드 계정은 자동 이관하지 않는다. Android 운영 서명과 두 실기기 검증도 후속이다.
