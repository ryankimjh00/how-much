# 한국어 메모·영수증 인식

## 1. 작업 출처
사용자 요청(2026-10-12), [Issue #14](https://github.com/ryankimjh00/how-much/issues/14).

## 2. 배경
손글씨 장보기 메모가 인식되지 않았다. Dart의 Korean 옵션과 달리 iOS에는 Latin 모델만 설치되어 있었으며, 플러그인이 오류 없이 영문 모델로 대체했다. Android에도 한국어 runtime dependency가 없었다.

## 3. 목표
촬영·앨범 사진을 실제 한국어 모델로 처리하고 기존 기록을 보존한다.

## 4. 범위
ML Kit 한국어 플랫폼 의존성, 메모 후보·수량 검증, 실제 손글씨 표본 회귀 검사, 앱 1.5.3(20), 검증 문서.

## 7. 다음에 바로 해야 할 것
사용자가 앱을 업데이트할 때 개발용 서명을 준비하고, 회귀 검사와 사용자가 오인식한 사진을 검사한다. 현재 요청은 코드 수정과 로컬 검증까지이며 기기 설치는 진행하지 않는다.

```sh
./scripts/app-local.sh
./scripts/check-ios.sh
# 연결된 기기와 개발용 서명 프로파일이 준비된 경우
./scripts/app-local.sh xcodebuild -workspace ios/Runner.xcworkspace \
  -scheme Runner -configuration Debug -destination 'id=<기기-ID>' \
  -derivedDataPath build/ios-local DEVELOPMENT_TEAM=2263MJ8YV6 \
  -only-testing:RunnerTests/RunnerTests/testKoreanHandwrittenMemoRecognition test
```

Flutter의 OCR 회귀 검사는 플랫폼 호출의 한국어 옵션, 검토 초안, 빈 결과·실패 시 자원 해제를 확인한다. 사진의 실제 인식률은 기기에서 ML Kit를 실행하는 `RunnerTests`로 확인한다.

## 8. 후속에 구현해야 할 것
다양한 필체·조명·영수증 표본으로 정확도를 확인한다.

## 9. 결정된 사항
- 사진은 Android·iOS 모두 기기 내 처리하며 외부 서버에 보내지 않는다.
- 영수증과 Android 메모는 한국어 ML Kit를 사용한다. iOS 메모는 2026-11-16부터 Apple Vision을 우선 사용하고 실패·미지원·상품 후보 없음일 때 ML Kit로 재시도한다.
- 테스트 사진은 RunnerTests에만 포함하고 운영 앱에 넣지 않는다.
- 패키지·Gradle 캐시는 내장 디스크에, Xcode 빌드 캐시는 `app/build/ios-local/`에 두고 기존 전역 설정을 유지한다.
- 잠금 파일의 SDK 종속 패키지 6개는 README 기준 Flutter 3.38.5 / Dart 3.10.4와 맞춘다.
- 메모 수량은 `개` 단위, `x`·`×`, 공백으로 구분된 숫자만 분리한다. 1~999 범위를 넘으면 원문을 유지해 사용자가 검토한다.

## 10. 아직 결정되지 않은 사항
다양한 실제 필체의 정확도에 따라 추가 인식 방식 필요 여부를 판단한다.

## 11. 임시 구현 / 주의사항
한국어 모델 포함이 모든 손글씨의 정확도를 보장하지는 않는다. 인식 결과는 사용자가 확인·수정한 뒤 저장한다.

## 2026-11-16 — 메모 전용 인식 경로 개선 (#14)

상태: 진행 중. iOS 인식 경로와 공통 목록 파서를 개선했으며, 실제 아이폰 재설치와 전체 실패 사진 해결은 미완료다.

- iOS 촬영·앨범 메모는 한국어 Apple Vision의 정확도 우선 모드로 읽는다. EXIF 방향을 반영하고 긴 변을 최대 3000px로 제한한다. 인식은 백그라운드에서 실행하며 사진·인식문을 저장하거나 외부 전송하지 않는다.
- 한국어 Vision 미지원, 채널 미등록, 인식 오류, 상품 후보 없음이면 기존 한국어 ML Kit로 다시 읽는다. 영수증의 인식·좌표 추출은 기존 경로를 사용한다.
- Android·iOS 공통으로 `장보기` 등의 메모 제목과 `1.`·`2)` 목록 번호를 제외한다. 쉼표·소수 수량의 일부를 유효한 정수 수량으로 잘라내지 않는다.
- 인식 도중 계정이 바뀌면 이전 계정의 초안을 열지 않는다. 결과는 자동 선택하지 않고 사용자가 수정·선택한 항목만 저장한다. 검토 안내도 정확도를 단정하지 않도록 바꿨다.
- Android 모델은 기존 한국어 ML Kit이며, 메뉴 사진의 모델 인식 실패는 계속 남아 있다. SDK 교체만으로 개선됐다고 판정하지 않는다.

Mac에서 운영 Swift 함수와 같은 코드를 실행한 장보기 표본은 10/11개이며 `양파→앙파`가 남았다. 사용자 메뉴 사진 두 장에서는 주요 메뉴명 4종을 읽었지만 `등심탕수육`의 반복 5회 중 각각 2회·1회만 읽었다. Mac 측정은 iPhone 검증을 대체하지 않는다. 기대 단어·반복 횟수는 인식기에 전달하지 않는다.

다음 검증: 실제 iPhone에서 촬영·앨범 원본, Vision 실패 시 ML Kit 재시도, 반복 메뉴 누락과 기존 기록 보존을 확인하고 삭제 없이 서명 빌드를 설치한다. 이 조건 전에는 Issue #14를 완료 처리하지 않는다.

`integration_test/memo_ocr_test.dart`는 운영 메모 인식기를 호출하며 기대 단어·반복 횟수로 실패를 판정한다. `MEMO_OCR_FIXTURES`에 `name`, `file`, `words`, 선택 사항인 `wordCounts`의 JSON 목록을 지정하고 `MEMO_OCR_FIXTURE_DIRECTORY`에 기기 내 사진 폴더를 지정한다. 명세가 없으면 건너뛴다. 개인 사진·명세는 커밋하지 않으며, 기록이 있는 기기의 `flutter drive`에는 `--keep-app-running`을 지정한다.

검증: Flutter 3.47.5 / Dart 3.13.4에서 포맷·정적 분석, Flutter 테스트 347개 통과·기존 자료 생성 시험 1개 건너뜀. iPhone SDK 27.2 대상 Swift 타입 검사와 iOS 앱·RunnerTests 무서명 컴파일 통과. 전체 빌드는 임시 프로젝트 설정으로 SPM을 끄고 iOS OpenCV를 CMake/Ninja로 컴파일했으며, 이 설정과 자동 생성된 잠금 파일 변경은 복구했다. iPhone 실기기 실행·설치는 미완료다.
