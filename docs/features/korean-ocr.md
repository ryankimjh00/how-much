# 한국어 메모·영수증 인식

## 1. 작업 출처
사용자 요청(2026-10-12), [Issue #14](https://github.com/ryankimjh00/how-much/issues/14).

## 2. 배경
손글씨 장보기 메모가 인식되지 않았다. Dart의 Korean 옵션과 달리 iOS에는 Latin 모델만 설치되어 있었으며, 플러그인이 오류 없이 영문 모델로 대체했다. Android에도 한국어 runtime dependency가 없었다.

## 3. 목표
촬영·앨범 사진을 실제 한국어 모델로 처리하고 기존 기록을 보존한다.

## 4. 범위
ML Kit 한국어 플랫폼 의존성, 메모 후보·수량 검증, 실제 손글씨 표본 회귀 검사, 앱 1.5.3(20), 검증 문서.

## 5. 구현해야 할 것

- [x] Android text-recognition-korean 16.0.1 포함

- [x] 실제 손글씨 장보기 사진의 플러그인 인식 회귀 검사
- [x] 코드 검사·Flutter 테스트·두 플랫폼 빌드
- [ ] iOS 플러그인의 실제 손글씨 인식 회귀 검사 실행
- [ ] iOS 27 아이폰 업데이트 설치·실행

## 7. 다음에 바로 해야 할 것
사용자가 앱을 업데이트할 때 개발용 서명을 준비하고, 회귀 검사와 사용자가 오인식한 사진을 검사한다. 현재 요청은 코드 수정과 로컬 검증까지이며 기기 설치는 진행하지 않는다.

```sh
./scripts/app-local.sh
./scripts/check-ios.sh
# 연결된 기기와 개발용 서명 프로파일이 준비된 경우
./scripts/app-local.sh xcodebuild -workspace ios/Runner.xcworkspace \
  -scheme Runner -configuration Debug -destination 'id=<기기-ID>' \
  -derivedDataPath build/ios-local DEVELOPMENT_TEAM=2263MJ8YV6 \
  -only-testing:RunnerTests/RunnerTests/testKoreanHandwrittenMemoRecognition test
```

Flutter의 OCR 회귀 검사는 플랫폼 호출의 한국어 옵션, 검토 초안, 빈 결과·실패 시 자원 해제를 확인한다. 사진의 실제 인식률은 기기에서 ML Kit를 실행하는 `RunnerTests`로 확인한다.

## 8. 후속에 구현해야 할 것
다양한 필체·조명·영수증 표본으로 정확도를 확인한다.

## 9. 결정된 사항
- 사진은 Android·iOS 모두 ML Kit Text Recognition v2 한국어 모델로 기기 내 처리하며 외부 서버에 보내지 않는다.
- iOS 촬영·앨범·메모·영수증이 사용하는 공통 Korean recognizer는 유지한다.
- 테스트 사진은 RunnerTests에만 포함하고 운영 앱에 넣지 않는다.
- 패키지·Gradle 캐시는 내장 디스크에, Xcode 빌드 캐시는 `app/build/ios-local/`에 두고 기존 전역 설정을 유지한다.
- 잠금 파일의 SDK 종속 패키지 6개는 README 기준 Flutter 3.38.5 / Dart 3.10.4와 맞춘다.
- 메모 수량은 `개` 단위, `x`·`×`, 공백으로 구분된 숫자만 분리한다. 1~999 범위를 넘으면 원문을 유지해 사용자가 검토한다.

## 10. 아직 결정되지 않은 사항
다양한 실제 필체의 정확도에 따라 추가 인식 방식 필요 여부를 판단한다.

## 11. 임시 구현 / 주의사항
한국어 모델 포함이 모든 손글씨의 정확도를 보장하지는 않는다. 인식 결과는 사용자가 확인·수정한 뒤 저장한다.

## 2026-11-09 — 메모 임시 사진과 과제 제출 검증

메모 촬영과 앨범 선택으로 앱이 만든 임시 사진은 `recognizeMemoPath(deleteAfterReading: true)`의 종료 경로에서 삭제한다. 빈 결과·플랫폼 오류에도 같은 정리를 수행한다. 외부에서 직접 전달한 경로는 기본적으로 삭제하지 않으며 사용자의 앨범 원본도 유지한다. 영수증 사진의 검토 흐름은 이번 변경 범위에 포함하지 않는다.

삭제 성공·실패 흐름과 외부 파일 보존을 단위 테스트로 확인한다. AI-ANT용 네이티브 실행 검증은 [단계별 제출 문서](ai-ant-submission.md)에 기록한다. 저장소의 종이 장보기 메모 한 장에 대한 오프라인 OCR 성공을 기존 다른 손글씨 실패 해결로 판정하지 않는다.

메모 수정창의 컨트롤러는 `DialogRoute.completed` 후 해제해 닫힘 애니메이션·키보드 전환 중 이미 해제된 입력 상태를 참조하지 않도록 했다. 작은 화면·키보드 전환 회귀 검사와 실제 Android 검토·수정·선택 저장을 통과했다.
