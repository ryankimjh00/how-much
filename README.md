# 얼마였지 Flutter

장보기 메모와 영수증을 기기에서 인식하고, 구매 가격을 기록·비교하는 Flutter 앱입니다.

원본은 [jhshin23/howmuch-shin](https://github.com/jhshin23/howmuch-shin)의 `chore/include-app` 브랜치(커밋 `411f1c3`)입니다.

## 포함 기능

- 장보기·구매 기록 기기 저장, 메모·영수증 OCR 검토
- 규격별 단가·차액·변동률 비교와 익명 가격 공유·해제
- 복구 코드 발급·복원, 로컬 우선 자동 동기화, 충돌 선택
- Figma 기반 크림·오렌지 UI와 최근 30일 가격 비교
- Kubernetes FastAPI·PostgreSQL 서버, DB PVC 2Gi

## 실행

Flutter 3.38.5 / Dart 3.10.4 기준입니다. Android 7.0(API 24), iOS 15.5 이상을 지원합니다.

```sh
cd app
flutter pub get
flutter run
```

한국어 OCR 모델은 Android Gradle과 iOS Podfile에 포함합니다. 네이티브 의존성 변경 후에는 앱을 완전히 다시 빌드해야 합니다. iOS에서는 `cd app/ios && pod install`로 의존성을 갱신합니다.

영수증 OCR 이식 1~3단계는 원문·사진 경로·좌표를 보존하고, 사진 박스 또는 후보 버튼에서 상품명과 금액·수량을 골라 기존 검토 화면으로 넘깁니다. 단가를 입력하면 수량을 곱해 결제금액으로 기록하며, 단가와 상품 결제금액 모두 수량을 기본 1개로 보여주며, 키보드 없이 위·아래 화살표로 수정할 수 있습니다. 검토 화면에는 개당 가격을 표시합니다. 후보는 길게 눌러 수정하며 취소하면 확정 전 변경을 되돌립니다. 좌표와 사진 경로는 구매 기록이나 서버에 저장하지 않습니다. 할인 입력·할인액 필드는 추가하지 않습니다. [단계별 범위와 검증](docs/features/flutter-migration.md)을 참고합니다. 문자열 파서의 초안이 비어도 OCR 원문이 있으면 좌표 후보 선택을 진행합니다. 분리된 금액의 `000` 잔존과 나뉜 용량 숫자 후보 문제는 이전 fresh에도 있어 이번 비교 수정에서 유지했습니다.

선택 순서는 **상품명들을 모두 선택 → 상품명 선택 완료(N개) → 각 상품의 금액을 모두 연결 → 수량 확인 → 검토**입니다. 첫 상품명은 전체 후보에서 고르고, 다음 이름은 첫 이름의 왼쪽 시작 위치를 기준으로 같은 열 아래에서 고릅니다. 선택 목록과 개수는 이름 선택 화면 상단에서 확인할 수 있습니다.

앨범에서 **한 장** 모드로 사진을 한 장만 선택하면 바로 보정·상품 선택·검토로 진행합니다. 여러 장 모드이거나 이미 모은 사진이 있으면 한 장을 선택해도 기존 목록에 추가합니다. 앨범 선택과 보정을 취소하면 기존 모드와 사진을 유지합니다.

긴 영수증은 촬영 화면의 **여러 장 찍기**에서 나눠 촬영하거나 **앨범**에서 바로 여러 장을 선택합니다. 두 장 이상을 고르면 미리보기 목록에 모으며 앨범을 다시 열거나 촬영해 사진을 더 추가할 수 있습니다. **촬영 완료 → 장마다 첫 상품명·수량·금액 선택 → 모든 장을 마친 뒤 전체 검토**로 진행합니다. 사진을 모으는 동안은 OCR을 실행하지 않고, 촬영 완료 후 각 장을 선택할 때 읽습니다. 각 장에서 수동 다중 상품 선택도 사용할 수 있습니다. 사진을 이어붙이거나 장 사이 중복을 자동으로 제거하지 않으며, 겹친 상품은 사용자가 최종 검토에서 제외합니다. 선택을 취소하면 완료한 앞 장은 유지하며, 불필요한 장은 건너뛸 수 있습니다. 검토에서는 사진을 넘겨 보고 각 항목을 원래 장의 사진에서 수정합니다. 최대 10장이고 기존 장별 확대·기울기 보정과 메모의 한 장 흐름은 유지합니다.

기본 서버는 `https://howmuch.monithub.org`입니다. 다른 서버는 `--dart-define=API_BASE_URL=https://...`로 지정합니다. 로컬 기능만 사용할 때는 `--dart-define=API_BASE_URL=`로 실행합니다. HTTP는 localhost 테스트만 허용합니다.

홈 우측 계정 버튼에서 **복구 코드 만들고 기록 연결**을 누르면 기기 기록을 새 계정으로 복사합니다. 코드는 한 번만 표시하므로 안전하게 보관해주세요. 다른 기기에서는 **기존 기록 복원**에 코드를 입력합니다. 코드를 아는 사람은 기록에 접근할 수 있습니다.

기기에 저장한 뒤 700ms 후 서버에 반영하고, 앱 활성 상태에서 30초마다 변경·실패한 전송을 확인합니다. 오프라인 기록과 충돌은 기기에 보존합니다. 복원한 계정에는 guest 기록을 자동으로 합치지 않습니다. 인증 세션은 Keychain/Keystore에만 저장합니다. 세션이 만료돼도 계정의 기기 기록은 유지합니다.

[서버·Swagger·테스트](server/README.md), [배포·백업·재시작 검증](deploy/README.md), [기능 상태](docs/features/cluster-sync.md), [Figma UI](docs/features/figma-ui.md), [개발·한국어 주석 기준](AGENTS.md)을 확인합니다.

기존 Flutter guest 기록 저장 키와 v4 형식은 유지합니다. Firebase SDK·이메일 로그인은 클러스터의 복구 코드 인증으로 교체했습니다. 이전 Firebase 계정과 Firestore 기록의 자동 이관은 포함하지 않으며 `firebase/`는 이전 구현 참고 자료입니다. React Native AsyncStorage도 자동 변환하지 않습니다.

패키지명은 기존과 같은 `com.todayone.todo`, 버전은 1.5.1(18)입니다. Android release는 아직 debug 서명을 사용하므로 스토어 배포 전 운영 키가 필요합니다. 클러스터는 단일 DB·단일 볼륨 복제이며 자동 백업은 후속 작업입니다.

Android 릴리스 최적화는 `app/android/app/proguard-rules.pro`에서 미포함 ML Kit 선택 언어 모듈(중국어·데바나가리·일본어)의 옵션 클래스 경고만 제외합니다. 한국어·기본 모델과 기존 최적화 설정은 유지합니다.

영수증 OCR 4단계는 검토 화면 위에 확대·이동 가능한 사진을 고정하고, 체크된 항목의 상품명과 선택 금액만 초록 박스로 표시합니다. 목록에서 “영수증에서 수정”은 수량 → 금액 순서로 진행하며 취소 시 기존 값과 박스를 유지합니다. “영수증에서 항목 추가”는 후보 선택 화면을, 일반 “품목 추가”는 직접 입력 편집창을 엽니다. 사진·영역 정보는 검토 중에만 유지합니다.

사진은 이전 fresh처럼 화면 가로폭에 맞춰 표시하고, 긴 영수증은 사진 영역 안에서 이동하며 확인합니다. 선택·검토 화면 모두 버튼 없이 제스처로 확대·이동합니다.

영수증 OCR 5~7단계는 후보가 없는 위치도 직접 박스를 지정·이동·크기 조절하고 부분 OCR 또는 직접 입력으로 적용합니다. 취소한 변경과 늦은 이전 응답은 반영하지 않으며 재인식 실패 시 이전 입력을 비웁니다. 상품명·수량·금액·날짜의 **영역 다시 읽기**는 원본 좌표에서 시작 박스를 줄이지 않고 가로6px·세로3px 단위로 조금씩 넓혀 한 번에 최대 5회 순서대로 인식합니다. 첫 유효 결과가 나오면 즉시 멈추고 입력란과 박스에 반영합니다. 실패 후 다시 누르면 다음 5회를 시도할 수 있으며, 후보를 선택하면 그 값이 읽힌 박스도 함께 적용합니다. 크기 조절 손잡이는 fresh처럼 박스 네 모서리 바깥에 배치해 작은 수량 박스에서도 다른 손잡이와 겹치지 않게 합니다. 손잡이는 불투명 배경·주황 테두리·확대 화살표가 있는 28px 버튼 모양으로 표시합니다. 긴 사진을 아래로 이동하거나 확대해도 손잡이는 현재 화면 좌표에 배치하고 28px 크기를 유지하여, 보이는 위치에서 크기를 조절할 수 있습니다. 전체 OCR이 비어도 사진 선택 화면에서 수동 영역 지정으로 진행할 수 있습니다.

수량과 상품명·단가·금액 중 하나가 한 행 또는 바로 붙은 두 행에 있으면 머리글로 보고, 마지막 머리글 행의 하단부터 상품명을 찾습니다. 다섯 머리글 단어가 모두 필요하지 않습니다. 머리글을 찾지 못하면 기존 탐색을 유지합니다.

끝까지 자동 선택 전 상품명·수량·금액 열을 각각 크롭 OCR하여 읽힌 행 위치를 임시 보관합니다. 각 상품명 기준 예상 위치와 가까운 탐색 행이 하나이면 그 위치에서만 반복 OCR하며, 실패해도 다른 위치의 숫자로 채우지 않습니다. 탐색 결과가 없거나 모호하면 기존 상대 위치 탐색을 유지합니다. 상품명 열과 처리 중인 상품명도 사진에 파란 박스로 표시합니다. 숫자로만 된 글자는 기존처럼 상품명 후보에서 제외합니다. 숫자가 10자리 이상이고 영문자가 한 글자뿐인 코드도 상품명 후보에서 제외하며, 한글이 함께 있거나 영문자가 두 글자 이상이면 유지합니다.

끝까지 자동 선택에서는 머리글이 있으면 그 아래 상품명을, 없으면 첫 상품 이후의 상품명을 각각 찾고, 각 상품명의 시작 위치에 첫 상품에서 정한 이름→수량·금액의 상대 거리를 적용해 기존 숫자를 연결하고, 누락된 영역만 추가로 읽습니다. 이후 상품명은 첫 상품명의 왼쪽 시작점에서 한 글자 정도의 오차 안에 있는 후보로 좁힙니다. 각 이름의 실제 시작점에서 수량·금액 상대 위치를 계산합니다. 디버깅을 위해 현재 재인식 영역을 파란 박스로 표시하고 사진 아래에 상품/필드/시도 횟수를 보여줍니다. 화면 밖의 영역은 확대 배율을 유지하며 따라갑니다. 박스 표시의 프레임 대기는 최대 150ms이며, 다음 OCR 호출 전 50ms 동안 화면/터치 이벤트를 처리해 진행 상태를 볼 수 있게 합니다. 전체 OCR에 숫자 후보가 없어도 예상 영역의 박스 경계를 미세하게 바꿔 최대 5회 시도하며, 첫 유효 인식 직후 중단합니다. 수량은 각 상품명에서 예상한 중심 위치, 금액은 예상한 우측 끝 위치를 확인하고 다음 상품 행을 침범하지 않습니다. 자동 수량 재인식은 처음 확정한 수량 박스의 폭·높이를 그대로 사용합니다. 크롭 숫자가 작게 잡혀도 위치만 참고하고 크기를 줄이지 않습니다. 수량 열 크롭도 같은 좌우 여백을 포함하며 미세 재시도와 사진/상품 행 경계 제한은 유지합니다. 직접 확인한 첫 기준값은 유지하며 재인식 실패한 항목은 체크를 해제해 검토에 남깁니다.

“첫 상품 기준 전체 자동 입력”은 첫 상품명 → 첫 수량 → 첫 금액을 기준으로 아래 상품들을 찾습니다. 금액 입력이 기본이며 “단가로 입력하기” 토글을 켜면 단가 입력으로 전환합니다. 두 방식 모두 수량 기준을 받습니다. 수량·금액이 누락되거나 모호한 상품과 결제 안내는 체크를 해제한 검토 후보로 남깁니다. 같은 행의 가까운 상품명 조각만 병합해 원본 크기로 다시 읽으며, 실패하면 기존 이름을 유지합니다. 저장·인증·동기화 모델과 할인 입력은 변경하지 않았습니다.

영수증 숫자 후보는 콤마 주변 공백·전각 콤마·전각 마이너스를 정리해 읽고 원문·좌표를 보존합니다. 원·통화 기호가 붙은 금액도 길게 누른 수정창에서 바로 적용할 수 있습니다. 단가로 입력한 검토 항목은 일반 편집창에서 수량만 바꿔도 단가를 유지해 총액을 다시 계산합니다. 총액을 직접 수정하면 이후 수량 변경에는 그 총액을 유지합니다. 취소한 변경은 원래 항목에 반영하지 않습니다.

사진 제스처는 fresh의 접점 추적과 휠 이벤트 소비 처리를 사용합니다. 사진 조작 중에는 목록 스크롤을 멈추고, 남아 있는 마지막 접점의 종료·취소 또는 터치패드 동작 종료 후 목록 스크롤을 다시 허용합니다. 확대·이동 상태는 사진 변환 컨트롤러로 유지하며 선택·검토 화면에 같은 처리를 적용합니다.

세로로 적힌 글씨는 상품명·숫자 후보에서 제외합니다. OCR 원문·좌표는 보존하고 인식 각도, 세로로 긴 여러 글자 박스, 촘촘히 이어진 한 글자 열로 방향을 판단합니다. 부분 OCR에도 같은 제외 기준을 적용합니다. 화면 방향은 변경하지 않습니다.

영수증 전체 사진 전처리는 fresh와 같은 순서로 수행합니다. 작은 사진을 긴 변1600px 목표·최대3배로 확대 → OCR → 글줄 기울기 추정 → 최초 원본에서 확대·회전한 사진 생성 → 재OCR 순서입니다. 표시 사진·후보 박스·부분 OCR은 최종 인식에 사용한 같은 사진의 좌표를 사용합니다. 대비 보정은 적용하지 않고 원본 파일은 덮어쓰지 않습니다. 재인식이 비거나 실패하면 첫 확대 사진과 첫 OCR 좌표를 함께 유지합니다. 실제 에뮬레이터 앨범의 트레이더스 원본에서 fresh와 출력 이미지 바이트가 같은 것을 확인했으며, 스너글 수량2 누락과 키친타월 금액 오인식은 남아 있습니다. 자세한 실제 결과는 `docs/features/flutter-migration.md`의 전체 사진 전처리 검증에 기록했습니다.

첫 상품 기준 전체 자동 입력 스위치는 상품명 선택 화면의 후보 목록 앞에 표시합니다. 후보가 많은 영수증에서도 먼저 켤 수 있으며, 자동 입력에서는 기준 상품명 하나를 선택합니다. 끄면 기존 수동 다중 상품명 선택을 사용합니다.

영수증 항목 선택은 전체 OCR 결과를 준비한 뒤 자동 입력으로 시작합니다. 금액 입력이 기본이고 “단가로 입력하기” 토글로 전환합니다. 자동 선택은 첫 상품명·수량·금액(또는 단가) 입력 칸을 한 화면에 함께 보여줍니다. 상품명을 고르면 주변 후보를 좁히며, 중간 완료 버튼 없이 세 기준을 모두 선택한 뒤 끝까지 자동 선택을 실행합니다. 첫 금액 후보는 상품명 주변의 오른쪽 숫자로 좁히되 선택한 수량의 세로 위치로 숨기지 않으며, 각 상품명에서 금액·수량의 상대 위치가 맞는 항목만 자동 체크합니다. “상품 수동 선택” 버튼으로 다중 상품명 수동 선택을 사용할 수 있고 사진 보정은 유지합니다.

OCR 선택 화면의 상시 안내 문구는 표시하지 않는다. 첫 화면의 **상품 수동 선택** 버튼으로 상품명 여러 개를 먼저 고른 뒤 각 금액·수량을 확인할 수 있다. 자동 입력 기본값과 사진 보정은 유지하며, 입력 오류·재인식 실패·진행 상태는 표시한다.

상품 선택 방식은 **상품 수동 선택 / 자동 선택** 버튼으로 고른다. 두 버튼은 같은 폭으로 나란히 배치하며, 그 아래에 전체 폭의 **단가로 입력하기** 토글을 표시한다. 자동 선택과 금액 입력이 기본이다.

OCR 수량 입력은 기본 **1개**이고 **위·아래 화살표**로 1~999개를 조절할 수 있다. 직접 입력과 후보 선택도 유지한다. 자동 선택은 행 연결에 필요한 첫 수량의 사진 위치를 선택하며, 화살표로 값을 고쳐도 그 위치는 유지한다. 다른 상품의 수량이 불확실한 경우는 자동으로 1개로 확정하지 않는다.

영수증 확인에서 상품을 길게 눌러 다른 상품 위에 놓으면 그 상품의 **세트 구성품**으로 묶인다. 구성품은 기준 상품 바로 아래에 표시하며 다른 상품으로 옮기거나 **세트 해제**로 분리할 수 있다. 가격·수량은 각각 보존하고 저장/복원·서버 동기화에 관계 ID를 유지한다. 서버의 새 `setParentId` 계약 반영이 필요하며, 세트 구성품은 단독 상품 가격 비교·공유에서 제외한다.

수량 증감 화살표는 기존 색상의 배경·테두리와 48px 터치 영역을 가진 버튼으로 표시합니다. 수량 1의 감소와 999의 증가는 비활성 색으로 구분합니다.

영수증 OCR 전에 **영수증 모양 보정** 화면에서 자동으로 찾은 네 모서리를 확인한다. 손잡이로 조정한 뒤 **보정 적용**하거나 **원본 사용**으로 진행한다. 여러 장은 촬영 완료 뒤 장마다 보정하며 취소한 장은 OCR하지 않는다. 보정·OCR은 기기 안에서 처리하고 원본 파일은 보존한다. 흰 배경·그림자·잘린 종이에서는 자동 경계를 직접 확인해야 하며 접힘·곡면까지 펴지는 것은 아니다.

자동 선택은 전체 OCR 후보를 기반으로 이름 열의 누락 후보를 추가하고, 숫자가 부족한 열만 추가 탐색한다. 전체·열·부분 OCR 후보는 원문과 좌표를 보존하며 누적한다. 같은 값·같은 위치만 중복 제거하고 다른 상품의 같은 수량은 따로 유지한다. 전체 OCR 안에서 겹쳐 반환된 동일 숫자도 중복 제거한다. 상품명 열에서 확인된 행은 원근으로 시작점이 조금 밀려도 검토에 유지하며, 숫자 열의 읽힌 값은 해당 상품 행에 속하는지 확인한 뒤 직접 재사용한다. 이미 읽혀 같은 상품 행으로 연결된 숫자는 첫 박스가 행보다 높아도 재사용한다. 새 크롭의 높이 제한 때문에 확정 값을 버리지 않는다. 이미 위치가 연결된 숫자는 다시 읽지 않으며 누락·불확실한 영역만 최대5회 부분 인식해 첫 성공에서 멈춘다. 실패한 필수 값은 검토에서 체크 해제하고 기존 다른 값은 유지한다. 완료한 누적 후보는 검토와 다시 선택에도 사용하며 취소한 결과는 반영하지 않는다.

사진을 읽은 직후에도 같은 값·같은 위치로 겹쳐 반환된 숫자는 박스와 버튼을 하나만 표시한다. 같은 한 자리 숫자가 같은 행에서 짧은 글자 높이의15% 이하 가로 틈으로 어긋난 경우도 중복으로 처리한다. 같은 판정을 자동 연결·숫자 누적·열 후보 재사용에도 적용해 이미 읽힌 수량을 중복 때문에 버리거나 불필요하게 재인식하지 않는다. 다른 행이나 떨어진 열의 같은 숫자, 같은 위치의 다른 값, 숫자가 아닌 원문은 유지한다. 재수정 시 이미 선택한 후보의 ID와 영역을 우선 보존하며 원본 OCR 응답은 변경하지 않는다.

자동 탐색은 `과세물품가액`, 같은 행의 `과세`+`부가세`, `과세`+`합계`, `결제`+`대상`+`금액` 중 하나가 인식되면 해당 행 위에서 종료한다. 열별 OCR 줄과 띄어 쓴 글자는 같은 행에서 왼쪽부터 묶으며, 서로 다른 행이나 `비과세`는 세금 정지 조건에 해당하지 않는다. 요약 행 경계와 수량 공백 경계 중 더 위쪽을 상품명·수량·금액 크롭과 자동 검토·부분 OCR에 공통 적용한다. 원문 후보는 보존한다.

자동 탐색은 수량 열의 인접 행 간격을 세어 중앙값의3배 이상 끊기면 직전 수량 행까지 읽는다. 사진 끝까지 세 행 분량의 공백이 있는 경우도 같은 기준으로 종료한다. 마지막 상품의 이름·금액 높이 오차를 위해 작은 아래 여백을 유지하며, 수량이3행 미만이면 경계를 추측하지 않는다. 범위 밖의 원문 후보는 보존하지만 자동 검토와 재인식에서는 제외한다. 실제 상품 중간에서 수량이 연속 누락되면 조기 종료될 수 있다.

자동선택은 현재 한 장의 사진을 한 번 디코딩하고 ML Kit 인식기를 재사용한다. 현재 상품의 수량·금액은 별도 인식기와 크롭 파일로 동시에 처리하고, 두 작업이 끝난 뒤 다음 상품으로 진행한다. 각 필드의 재시도는 최대 5회 순차로 수행해 첫 성공 직후 중단한다. 영역마다 자르기·PNG 생성·OCR은 계속 수행하며, 이미 연결된 전체·열 OCR 숫자는 재사용하고 누락 영역만 자르기·PNG 생성·OCR을 수행한다. 화면 대기는 기존 흐름을 유지한다. 완료·취소·실패 시 진행 중인 인식이 끝난 뒤 인식기·사진·임시 파일을 정리한다. 여러 장의 디코딩 사진을 동시에 보관하지 않는다.

자동 상품명 후보는 첫 상품명 왼쪽 시작점을 기준으로 첫 박스와 후보 박스 중 큰 높이만큼(한 글자 정도)의 좌우 오차를 허용한다. 열 밖 후보는 자동 검토·재인식에서 제외하며 이름 길이나 오른쪽 끝은 제한하지 않는다. 원문과 수동 선택 후보는 보존한다. 같은 열의 하단 안내 조각까지 이 조건만으로 상품과 구분하지는 못한다.

영역 재인식 경계는 확대 3px·축소 1px를 기준으로 하며 가로 확대는 6px로 더 크게 허용한다. 첫 박스는 그대로 읽고 실패 재시도 시 기존 1~4 배율을 이어간다. 자동 인식은 해당 상품 행을 넘어가지 않는다.

자동 재인식의 수량·금액 박스 높이는 첫 상품에서 사용자가 정한 높이보다 줄이지 않는다. 작은 OCR/열 후보는 위치를 참고하며 미세 경계 축소도 이 높이 아래로 내려가지 않는다. 사진·상품 행 안에 기준 높이가 들어가지 않으면 다른 행을 침범하지 않고 체크 해제된 검토 항목으로 남긴다. 수동 영역 편집의 축소는 유지한다.

자동 인식 진행 중에는 현재 상품의 수량·금액 박스와 각각의 시도/성공 횟수를 함께 표시한다. 새 상품으로 넘어가거나 취소·완료하면 이전 표시를 지운다. 두 영역의 합친 범위를 따라가며 OCR 원본 좌표는 바꾸지 않는다.

첫 상품의 수량·금액은 서로 다른 줄에서도 각각 지정할 수 있다. 수량을 바꿔도 선택한 금액을 유지하며 같은 후보를 두 필드에 선택한 경우에만 금액 선택을 해제한다. 자동 실행 전에는 각 영역이 첫 상품 시작부터 다음 상품명 경계 사이인지 검사한다.

영수증 첫 상품 선택 전에는 전체 OCR 원문의 글자·숫자·기호 위치에 선택 가능한 박스를 표시한다. 상품명 후보 분류로 금액·수량·상품코드를 숨기지 않으며 용도는 사용자가 판단한다. 첫 선택 이후에는 기존 상품명 열과 수량·금액 후보 좁히기를 유지한다.

첫 상품 주변의 숫자 후보는 글자 박스의 위·아래 범위를 포함한 행 영역으로 판정한다. 이미 묶은 상품명 행 다음의 두 행을 순서대로 사용하며, 별도의 중심점 경계 때문에 수량이 있는 첫 행을 건너뛰지 않는다.

한 글자로 인식된 영역은 첫 전체 OCR 표시부터 선택 화면에서 사방4px의 표시·터치 여백을 둔다. 수량 선택 시 이 여백을 사진 좌표로 환산해 실제 열 탐색과 부분 OCR의 기준 크기에 반영한다. 원본 OCR 좌표는 보존하고 다시 선택해도 중복 확대하지 않으며 직접 수정한 영역은 확정한 크기를 그대로 쓴다.

영수증 검토의 구매일 옆 **영수증에서 날짜 수정**에서 현재 장의 날짜 영역을 지정·조절하고 다시 읽거나 직접 입력할 수 있다. 적용 전에는 기존 구매일을 유지하며 취소한 수정은 반영하지 않는다. 날짜 줄의 시간은 제외하고 `yyyy-MM-dd`로 정규화하며, 존재하지 않거나 미래인 날짜는 적용하지 않는다. 장별 적용 영역은 검토 화면에서 다시 열 때 복원하며 저장 모델은 기존 구매일 필드를 그대로 사용한다.

자동 숫자 탐색은 좌우 각각 최소4px 또는 기준 높이의15% 여백을 더한다. 영역 다시 읽기는 시작 영역보다 줄이지 않고 바깥으로 넓히는 조합만 사용하며 사진·상품 행 경계를 유지한다. 사람이 손잡이로 직접 크기를 줄이는 동작은 유지한다.

자동 기준의 수량을 영역 지정으로 적용하면 금액 선택으로 진행한다. 금액에서 숫자만인 천 단위 점 표기는 사용자 지정에 따라 콤마로 통일한다(`9.600 → 9,600`, `100.000 → 100,000`, `1.234.567 → 1,234,567`). OCR 원문·좌표와 날짜·용량 표기는 유지하며 일반 소수나 잘못된 그룹은 금액으로 확정하지 않는다.

여러 장 영수증은 촬영·앨범 추가를 합쳐 최대 10장까지 모을 수 있습니다. 영수증 확인 화면의 사진 전환과 상품 목록에는 `첫째 장`, `둘째 장`, …, `열째 장`으로 장 순서를 표시합니다.

자동 선택에서 첫 상품명과 수량·금액이 모두 다른 행이면 상품명 열의 같은 행 좌표로 분리된 조각을 한 상품으로 묶습니다. 글자가 다르게 읽히거나 문자열이 잘려도 병합을 막지 않으며, 이때 기존 이름 조각을 유지합니다. 수량이나 금액이 상품명과 같은 행이면 기존의 가까운 조각·숫자 장벽을 사용하는 보수적인 병합을 유지합니다. 같은 행에 걸치기만 한 오른쪽 조각은 별도 상품으로 확정하지 않습니다.

- 교보 스윗츠의 중복 수량1: 같은 한 글자 숫자의 작은 좌표 차이는 글자 높이20%까지 표시·자동 연결·열 재사용에서 동일하게 합친다. 다른 행·열·값은 보존한다. 프리즘의 실제 수량 재인식 실패는 아직 해결되지 않았다. 상세 검증은 `docs/ocr-debug/kyobo-second-20261011/README.md` 참조.

- 영수증 확인의 펜 편집창에서 수량은 위·아래 삼각형 버튼으로1~999개 조절할 수 있고 직접 입력도 유지한다. “확인했어요”를 누르면 유효한 수정과 함께 항목을 체크한다. 취소하면 수량·금액·기존 체크 상태를 유지한다.

- 영수증 촬영의 한 장/여러 장 모드를 바꾸면 이전 사진 목록과 장별 OCR·선택 캐시를 함께 초기화한다. 한 장 모드에서 고른 사진 한 장은 이전 여러 장 목록에 누적하지 않는다. 여러 장 모드의 “새 영수증”으로 목록을 비우고 다른 영수증을 시작할 수 있다. 같은 모드 재선택·앨범 취소·현재 영수증의 다음 장 추가는 목록을 유지한다.

- 자동 선택의 열 OCR은 누락된 수량 열만 보완한다. 상품명·금액 열 재검사는 제외하고 전체 OCR 후보를 유지한다. 이름 조각 병합은 전체 OCR의 기존 글줄·좌표를 사용한다. 누락된 개별 수량·금액의 부분 재인식과 직접 수정은 유지한다. 전체 OCR에서 빠진 상품명은 수동으로 추가해야 한다.


자동 선택에서 누락 수량을 재인식할 때 같은 높이의 좌우 가격 문맥을 함께 읽고, 지정한 수량 박스 안의 숫자만 사용한다. 실제 교보 둘째장 수량1은 원본10/11개·별도 원근 보정11/11개를 읽었다. 펩시 행의1은 여전히 실패한다. 상세 시험 기록은 [수량1 비교](docs/ocr-debug/quantity-one-20261011/README.md)를 참조한다.


자동 금액 연결의 가로 위치 오차는 첫 금액과 현재 상품명 중 큰 글자 높이를 반영한다. 교보 하단의 큰 글자·원근 차이로 이미 읽힌3,500원을 버리고 왼쪽을 재탐색하던 문제를 수정했다. 행 소속과 유일 후보 검증은 유지한다.


## OCR 모델 독립 비교

ML Kit·PaddleOCR·Tesseract를 같은 실제 사진과 영역으로 각각 시험했다. 생산 앱의 인식기는 변경하지 않았다. 원본별 정확도·실패 원문·재현 조건과 실기기 측정의 한계는 [비교 보고서](docs/ocr-comparison/20261011/README.md)에 기록했다.

후속으로 세 엔진을 모두 같은 Android 에뮬레이터에서 독립 실행했다. 기본 217건·공통 여백 45건과 Tesseract 추가 설정을 포함해 8회·1,059건을 기록했다. [Android 비교 결과](docs/ocr-comparison/20261012-android/README.md)와 [비교 빌드 방법](app/android/ocr_compare/README.md)을 참조한다.

사용자 요청으로 현재 Android 기본 OCR은 PaddleOCR로 전환했다. 전체·영역·수량·금액 재인식에 같은 엔진을 사용하며 내부 검출 최대 변은1600px다. 기존 Android7.0(API24)·iOS15.5 기준을 유지한다. iOS는 기존 ML Kit를 사용한다. Android7.0·15 에뮬레이터에서 실제 교보 사진의 전체·부분 인식과 세션 재사용을 검증했다. 기본 APK에는 Paddle 모델만 추가하고 비교 사진·Tesseract는 제외한다. [전환 검증](docs/ocr-debug/paddle-switch-20261012/README.md)을 참조한다.

[온디바이스 AI 기술 조사 보고서 PDF](docs/research/on-device-ai-survey-20261011/얼마였지_온디바이스AI_기술조사보고서_20261011.pdf)는 Android·iOS·크로스플랫폼 AI 개발 도구, OCR 경량 모델, 기본 API 예시와 메모·영수증 OCR 요구사항 구현 방법을 다룬다. 실제 영수증의 ML Kit·PaddleOCR·Tesseract 독립 비교를 포함하며 실행 환경 차이를 구분한다. 최종 기술 선정은 하지 않는다.


자동 선택의 첫 상품은 사람이 확정한 이름·수량·금액으로 검토 항목을 먼저 만든다. 다른 상품의 행·머리글/종료 경계·가격 중복·구매 안내 판정·상품명 병합에 영향을 받지 않으며 자동 재인식으로 덮어쓰지 않는다. 잘못된 숫자 범위 등 첫 입력 자체의 검증은 유지한다. 나머지 상품만 자동 판정한다.
