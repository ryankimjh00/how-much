# 얼마였지 Flutter

장보기 메모와 영수증을 기기에서 인식하고, 구매 가격을 기록·비교하는 Flutter 앱입니다.

원본은 [jhshin23/howmuch-shin](https://github.com/jhshin23/howmuch-shin)의 `chore/include-app` 브랜치(커밋 `411f1c3`)입니다.

## 포함 기능

- 장보기·구매 기록 기기 저장, 메모·영수증 OCR 검토
- 규격별 단가·차액·변동률 비교와 익명 가격 공유·해제
- 복구 코드 발급·복원, 로컬 우선 자동 동기화, 충돌 선택
- Figma 기반 크림·오렌지 UI와 최근 30일 가격 비교
- Kubernetes FastAPI·PostgreSQL 서버, DB PVC 2Gi

## 실행

프로젝트 요구사항은 Flutter 3.38.0 이상 / Dart 3.10.4 이상 4.0 미만입니다. 이번 Android 검증에는 Flutter 3.47.5 / Dart 3.13.4를 사용했습니다. 최소 OS 설정은 Android 7.0(API 24), iOS 15.5입니다.

```sh
cd app
flutter pub get
flutter run
```

한국어 OCR 모델은 Android Gradle과 iOS Podfile에 포함합니다. 네이티브 의존성 변경 후에는 앱을 완전히 다시 빌드해야 합니다. iOS에서는 `cd app/ios && pod install`로 의존성을 갱신합니다.

영수증은 **촬영 또는 앨범 선택 → 사진 보정 → 상품 선택 → 영수증 확인 → 구매 기록 저장** 순서로 입력합니다. 자동 선택·수동 선택·여러 장 입력 방법은 아래 [영수증 OCR](#영수증-ocr)을 참고합니다.

iOS는 `UIScene`으로 화면을 시작하고 엔진 초기화 후 플러그인을 등록합니다. Xcode 27 / iOS 27 SDK로 빌드할 때도 이 설정을 유지해야 합니다. 실제 아이폰에 업데이트할 때는 `flutter build ios --release`로 빌드하고, 기존 앱을 삭제하지 않고 설치합니다. [iOS 호환성·검증 상태](docs/features/ios-27-compatibility.md)를 확인합니다.

기본 서버는 `https://howmuch.monithub.org`입니다. 다른 서버는 `--dart-define=API_BASE_URL=https://...`로 지정합니다. 로컬 기능만 사용할 때는 `--dart-define=API_BASE_URL=`로 실행합니다. HTTP는 localhost 테스트만 허용합니다.

홈 우측 계정 버튼에서 **복구 코드 만들고 기록 연결**을 누르면 기기 기록을 새 계정으로 복사합니다. 발급·복원한 코드는 기기 보안 저장소에 보관하며 **계정 · 동기화 → 복구 코드 다시 보기**에서 확인·복사할 수 있습니다. 다른 기기에서는 **기존 기록 복원**에 코드를 입력합니다. 코드를 아는 사람은 기록에 접근할 수 있으므로 안전하게 보관해주세요.

이전 버전에서 연결한 계정은 보관한 코드를 한 번 입력해 다시 연결해야 다시 보기를 사용할 수 있습니다. 서버에는 해시만 있어 잃어버린 기존 코드를 재조회할 수 없습니다. 로그아웃하면 이 기기에 보관한 코드와 세션을 함께 지웁니다.

기기에 저장한 뒤 700ms 후 서버에 반영하고, 앱 활성 상태에서 30초마다 변경·실패한 전송을 확인합니다. 오프라인 기록과 충돌은 기기에 보존합니다. 복원한 계정에는 guest 기록을 자동으로 합치지 않습니다. 인증 세션과 복구 코드는 Keychain/Keystore에만 저장합니다. 세션이 만료돼도 계정의 기기 기록과 보관한 복구 코드는 유지합니다.

## 영수증 OCR

### 현재 인식 엔진

Android·iOS 모두 **한국어 ML Kit**를 사용합니다. 영수증과 손글씨 메모는 같은 OCR 연결부를 사용하며, 메모의 목록 생성 로직은 유지합니다. Paddle·Tesseract 연결, 해당 모델·라이브러리와 엔진 선택 빌드 옵션은 제거했습니다.

사진 보정과 후보 좌표 처리는 Dart에서 수행합니다. Android는 Flutter 기본 `MainActivity`를 사용하고, ML Kit의 네이티브 연결은 Flutter 플러그인이 담당합니다.

### 사진 선택과 보정

- **한 장 찍기:** 촬영하거나 앨범에서 한 장을 선택해 보정·상품 선택으로 진행합니다.
- **여러 장 찍기:** 촬영과 앨범 추가를 합쳐 최대 **10장**을 모읍니다. 앨범에서 한 장씩 추가하거나 여러 장을 함께 선택할 수 있습니다.
- 사진을 모을 때는 OCR을 실행하지 않습니다. 촬영 완료 후 각 장을 보정하고 읽습니다.
- 장마다 첫 상품명·수량·금액을 새로 지정하고, 모든 장을 마친 뒤 전체 영수증 확인 화면으로 이동합니다. 수동 선택도 장마다 사용할 수 있습니다.
- 사진을 이어붙이거나 장 사이 중복 상품을 자동 제거하지 않습니다. 겹쳐 찍힌 상품은 최종 검토에서 사용자가 제외합니다.
- 한 장/여러 장 모드를 바꾸거나 **새 영수증**을 시작하면 이전 사진과 장별 선택 상태를 비웁니다. 앨범 선택 취소와 현재 영수증의 다음 장 추가는 기존 목록을 유지합니다.

**영수증 모양 보정**에서 자동으로 찾은 네 모서리를 확인하고 손잡이로 조정한 뒤 **보정 적용** 또는 **원본 사용**으로 진행합니다. 원본 파일은 덮어쓰지 않습니다. 흰 배경·그림자·잘린 종이에서는 경계를 직접 확인해야 하며, 접힘이나 곡면을 펴는 기능은 아닙니다.

전체 사진은 작은 경우 긴 변 1600px를 목표로 최대 3배 확대해 읽고, 글줄의 기울기가 확인되면 최초 입력 사진에서 확대·회전을 적용해 다시 읽습니다. 대비 보정은 하지 않습니다. 재인식이 비거나 실패하면 첫 사진과 첫 OCR 좌표를 함께 유지합니다. 표시 사진·후보 박스·부분 OCR은 같은 사진 좌표를 사용합니다.

### 상품 선택과 가격 입력

기본값은 **자동 선택 + 상품 결제금액 입력**입니다. **상품 수동 선택 / 자동 선택** 버튼 아래의 **단가로 입력하기** 토글로 금액의 의미를 바꿉니다. 두 방식 모두 수량을 확인합니다.

| 입력 방식 | 입력 예 | 기록되는 상품 결제금액 | 검토할 개당 가격 |
| --- | --- | --- | --- |
| 금액 입력 | 80,940원, 수량 3 | 80,940원 | 26,980원 |
| 단가 입력 | 26,980원, 수량 3 | 80,940원 | 26,980원 |

**자동 선택**에서는 첫 상품명·수량·금액(또는 단가)을 한 화면에서 지정하고 **끝까지 자동 선택**을 누릅니다. 수량과 금액은 서로 다른 줄에서도 지정할 수 있습니다. 직접 확인한 첫 상품은 다른 상품의 판정이나 재인식 결과로 덮어쓰지 않습니다.

**상품 수동 선택**은 다음 순서입니다.

1. 상품명들을 먼저 선택합니다. 첫 이름 이후에는 첫 이름의 왼쪽 시작점과 비슷한 열의 아래쪽 후보를 보여줍니다.
2. 선택한 상품들의 금액을 차례로 연결합니다. 상품명 오른쪽과 가까운 아래 행의 숫자를 우선 제시합니다.
3. 각 상품의 수량을 확인하고 검토로 진행합니다.

처음에는 전체 OCR의 글자·숫자·기호 박스를 표시하며 용도는 사용자가 정합니다. 박스와 후보 버튼은 같은 항목을 가리킵니다. 후보는 길게 눌러 수정할 수 있고, 직접 입력과 영역 지정도 가능합니다.

수량 입력은 **기본 1개**, 위·아래 버튼으로 **1~999개**를 조절합니다. 자동 선택에서는 첫 수량의 사진 위치도 지정해야 합니다. 뒤 상품의 필수 수량을 못 읽었다고 임의로 1개로 확정하지 않습니다. 금액은 0~9,999,999원 범위이며 단가와 수량을 곱한 결제금액도 이 범위 안이어야 합니다. 별도 할인 입력·할인액 필드는 추가하지 않습니다.

숫자만인 천 단위 점 표기는 금액 후보에서 콤마로 통일합니다. 예를 들어 `9.600 → 9,600`, `100.000 → 100,000`입니다. 날짜·용량 표기와 OCR 원문은 유지합니다.

### 자동 선택의 처리 기준

- **전체 OCR 후보를 유지·누적**하고, 누락된 **수량 열만** 추가 검사합니다. 상품명·금액 열은 다시 읽지 않으며, 전체 OCR에서 빠진 이름은 수동으로 추가해야 합니다.
- 첫 상품명의 왼쪽 시작점과 비슷한 열에서 이름을 찾고, 각 이름에서 첫 기준의 수량·금액 상대 위치를 적용합니다. 이름 길이나 오른쪽 끝으로 제외하지 않습니다.
- 이미 해당 상품 행으로 연결된 숫자는 재사용합니다. 누락·불확실한 수량·금액 영역만 부분 OCR로 보완하며, 현재 상품의 행 경계를 넘지 않습니다.
- 수량 재인식은 처음 지정한 수량 박스의 폭·높이를 기준으로 하고, 금액 박스도 첫 기준의 높이보다 작게 줄이지 않습니다. 사진·상품 행의 경계 제한은 유지합니다.
- 부분 재인식은 **최대 5회**, **첫 유효 결과에서 중단**합니다. 필수 값이 없거나 모호하면 항목을 체크 해제한 상태로 검토에 남깁니다.
- 같은 값·같은 위치로 겹친 숫자는 중복 제거하지만, 다른 위치의 동일 숫자는 별개 후보로 유지합니다.
- 수량과 상품명·단가·금액 중 하나가 같은 행 또는 붙어 있는 두 행에 있으면 머리글 아래부터 찾습니다. 세금·결제 요약 행과 수량 행 간격도 종료 판단에 사용합니다. 공백 안에 이미 읽힌 상품명이 있으면 수량 누락만으로 뒤 상품을 버리지 않습니다.
- 같은 행에서 나뉜 상품명 조각은 숫자와의 배치를 확인해 병합합니다. 첫 기준 상품의 위치·이름은 보존하고, 이름과 숫자가 같은 행에 있는 영수증은 보수적으로 병합합니다.

자동 선택 중에는 처리 중인 상품과 수량·금액 탐색 박스, 시도·성공 횟수를 표시합니다. 한 장의 사진과 인식기를 재사용하고, 수량·금액은 별도 인식기로 병렬 처리한 뒤 다음 상품으로 넘어갑니다. 완료·취소·실패 시에는 진행 중인 호출이 끝난 뒤 자원을 정리합니다.

### 검토·수정·세트 구성품

영수증 확인에서는 사진을 확대·이동하고 항목 목록을 따로 스크롤할 수 있습니다. 체크된 항목의 **상품명과 금액**만 초록 박스로 표시합니다. 여러 장은 **첫째 장, 둘째 장, …, 열째 장**으로 전환하며, 각 항목은 원래 사진에서 수정합니다.

- **영수증에서 수정:** 기존 항목의 수량 → 금액을 다시 선택합니다. 취소하면 기존 값과 박스를 유지합니다.
- **영수증에서 항목 추가:** 사진의 후보 또는 직접 지정한 영역으로 추가합니다.
- **일반 품목 추가·펜 편집:** 직접 입력 편집창을 엽니다. 수량 버튼과 직접 입력을 사용할 수 있습니다. **확인했어요**를 누르면 유효한 수정과 함께 항목을 체크합니다.
- **영수증에서 날짜 수정:** 현재 장의 날짜 영역을 지정하거나 직접 입력합니다. 날짜를 검증한 뒤 적용하며 취소하면 기존 구매일을 유지합니다.

상품을 길게 눌러 다른 상품 위에 놓으면 그 상품의 **세트 구성품**으로 묶입니다. **세트 해제**로 분리하거나 다른 상품으로 옮길 수 있습니다. 구성품을 펜 편집창에서 개별 수정하고 **확인했어요**를 누르면 **그 구성품만 독립 항목으로 분리·선택**합니다. 취소하면 기존 수량·금액·세트 관계·선택 상태를 유지하고, 기준 상품과 다른 구성품은 바꾸지 않습니다.

세트 관계는 로컬 저장·복원과 서버 동기화 데이터의 `setParentId`로 유지하며, 구성품 가격을 임의 배분하지 않습니다. 구성품은 단독 상품 가격 비교·공유에서 제외합니다. 서버 데이터 계약은 [서버 README](server/README.md)를 참고합니다.

### 영역 지정과 재인식

OCR 후보가 없어도 상품명·수량·금액·날짜 영역을 직접 지정하고 손잡이로 이동·크기를 조절할 수 있습니다. **영역 다시 읽기**는 시작 박스에서 바깥쪽으로 경계를 조금씩 넓혀 최대 5회 순차 인식하고, 첫 유효 결과에서 멈춥니다. 실패하면 입력값을 비워 직접 확인하게 하며, 다시 읽기를 재시도할 수 있습니다. 사용자가 손잡이로 직접 박스를 줄이는 동작은 가능합니다.

확대·이동 후에도 박스는 사진 좌표를 사용합니다. 취소한 변경과 영역 이동 전에 요청한 늦은 OCR 응답은 적용하지 않습니다. 세로 글씨는 상품명·숫자 후보에서 제외하고, 사진과 영역 정보는 검토 중에만 유지하며 구매 기록이나 서버에 저장하지 않습니다.

### 확인된 검증과 남은 범위

- 현재 앱 코드의 Flutter 테스트: **302개 통과, 1개 건너뜀**. 고정된 OCR 응답을 사용하는 테스트는 후보 처리·좌표·취소·저장 등을 검증하며 실제 사진 인식 정확도와 구분합니다.
- 정적 검사: 기존 `screens.dart`의 `unawaited_return_in_try_block` 경고 1개가 남아 있습니다.
- 최신 ML Kit Debug APK를 Android 에뮬레이터에 기존 데이터 유지 방식으로 설치하고 앱 실행을 확인했습니다. ARM64 Release APK도 ML Kit 복원 시점에 빌드·서명·포함 자원을 검사했습니다.
- 이번 복원·리팩터링 버전의 실기기 인식 정확도·속도와 iOS 실행은 별도로 확인해야 합니다. 모든 영수증에서 상품명·수량·금액이 정확히 연결된다고 보장하지 않습니다. 자동 결과를 사진과 대조한 뒤 저장해야 합니다.

기능별 상세 이력은 [Flutter 기능 기록](docs/features/flutter-migration.md), 릴리스 환경의 주의사항은 [배포 전 확인 사항](docs/release/pre-deploy-discussions.md)에 남아 있습니다. 과거 문서의 Paddle 실행·정확도·속도 기록은 당시 버전의 결과이며 현재 ML Kit 성능을 뜻하지 않습니다. 이전 엔진 연결 코드는 Git 이력에서 확인할 수 있습니다.
